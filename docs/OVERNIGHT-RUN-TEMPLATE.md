# 야간 연속 실행 계획 — [대상 로드맵·Task 범위] (YYYY-MM-DD 밤)

사용자가 자리를 비운 동안 [태스크 관리 도구 / 로드맵]에 등록된 [Task 범위]를 한 세션에서 이어서 실행하기 위한 규칙입니다. YYYY-MM-DD에 사용자와 결정했습니다.

> **이 문서가 우선합니다.** 이번 실행에 한해 [평소 규칙 — 예: "병합은 사용자가 한다"]보다 이 문서를 따릅니다. 실행이 끝나면 그 권한은 원래대로 사용자에게 돌아갑니다.

**쓰는 법**

1. 이 파일을 `docs/overnight-run-YYYY-MM-DD.md`로 복사합니다.
2. **1절(사용자 결정)** 은 반드시 사용자와 함께 채웁니다. 되돌리기 어려운 일(병합·배포·운영 DB 변경·외부 발송)을 에이전트에게 맡길지는 사용자가 정합니다. 정하지 않은 항목은 "하지 않음"이 기본값입니다.
3. 해당 없는 절(예: 배포가 없는 프로젝트의 5절 7~9번, 6·7절)은 지웁니다.
4. 실행이 끝난 뒤에도 이 파일은 지우지 않습니다. 10절이 실행 기록입니다.

## 시작 명령

사용자가 `/clear` 뒤 아래 한 줄로 시작합니다. `/loop`는 턴이 도중에 끝나도 다시 깨워 이어 가게 하는 안전망입니다.

```text
/loop docs/overnight-run-YYYY-MM-DD.md 규칙대로 다음 작업을 이어서 진행해. 모든 Phase가 끝나거나 막히면 10절을 채우고 루프를 멈춰.
```

## 1. 사용자 결정 (YYYY-MM-DD)

| --- | --- | --- |

## 3. 시작 점검 (한 번)

1. 기본 브랜치로 옮겨 최신으로 맞추고, 작업 트리가 깨끗한지 확인
2. 필요한 환경변수가 있는지 확인 — **값은 출력하지 말고 있는지만**(길이 정도) 확인. 없으면 그에 의존하는 확인만 아침으로 미룸
3. `[검증 명령]` · `[빌드 명령]` 통과. 결과를 기준선으로 저장(테스트 수, 빌드 산출물 목록 등 나중에 비교할 것)
4. 쓸 도구(MCP 서버, CLI, 외부 서비스) 연결 확인
5. 외부 의존의 현재 상태 확인(승인 대기 중인 키, 한도 등) → 결과를 10절에 기록
6. 검증에 필요한 서버를 백그라운드로 띄움

## 5. Phase 한 바퀴

1. 최신 기본 브랜치에서 브랜치 생성. 앞 Phase가 병합되지 못했다면 그 브랜치 위에 이어 만들고, 이 Phase도 병합하지 않음
2. 작업마다: 태스크 시작 처리 → 담당 서브에이전트에게 작업 상세와 **이 문서 경로**를 넘겨 구현 · 작업별 검증 → 메인이 diff 확인 · `[검증 명령]` → 커밋 → 태스크 완료 처리
3. Phase 끝: `code-reviewer`로 Phase 전체 diff 리뷰 → 🔴 · 🟠 반영 → `[빌드 명령]` 결과가 기준선(+ 로드맵이 허용한 변화)과 같은지 확인
4. push → PR 생성. 본문에 작업 목록 · 검증 결과 · DB 변경이 있으면 **되돌리는 방법**
5. CI를 기다림 → 실패하면 고쳐서 다시 push(3번까지)
6. **병합 조건**을 모두 만족할 때만 병합(1절 N1이 허용한 경우)
   - CI 체크 전부 성공
   - Phase의 모든 작업이 완료 기준 통과(막힌 작업은 브랜치에서 빠져 있음)
   - 필수 리뷰의 🔴 지적이 남아 있지 않음
   - 기준선 유지, 비밀을 다루는 Phase는 산출물에 비밀 값 없음
7. **배포 확인** — 병합 커밋의 배포 상태가 성공이 될 때까지 기다림(최대 [N]분)
8. **운영 점검** — 로그아웃 상태 요청 + 로그인 상태 실제 조작

   | 대상 | 기대 |
   | --- | --- |
   | [공개 경로] | 200 |
   | [보호 경로] | 로그인으로 이동 |
   | [세션 없이 불리는 엔드포인트](비밀 없음) | 401 또는 503. 리다이렉트 · 500이면 실패 |
   | [테스트 계정]으로 이번 Phase가 바꾼 화면 한 곳 | 정상 표시, 콘솔 오류 0 |

9. **롤백** — 배포 실패 또는 운영 점검 실패면 즉시
   1. 병합 커밋을 되돌리는 PR → 체크 통과 → 병합 → 운영 점검 다시
   2. 원인이 DB면 PR 본문의 되돌리는 방법을 드라이런 뒤 적용
   3. **그 뒤로는 병합하지 않음.** 남은 작업은 브랜치에서만 진행하고 PR을 열어 둔 채 10절에 기록
10. 로드맵 체크박스 · 진행 상황은 그 Phase 브랜치 안에서 갱신
11. 병합 뒤 10절에 한 줄 추가 → 다음 Phase

## 6. 환경변수가 없어도 깨지지 않게 (fail-closed)

자리를 비운 동안 배포되는 코드는 배포 환경에 새 환경변수가 **아직 없을 수 있다**고 가정합니다. 새 변수가 없어도 빌드가 성공하고, 관련 기능만 조용히 꺼져야 합니다.

| 변수 | 없을 때 동작 |
| --- | --- |
| `[이름]` | [기능을 숨김 / 엔드포인트가 503 / 호출을 건너뛰고 경고 로그] |

- 키 확인은 모듈을 읽을 때가 아니라 **요청이 올 때** 합니다. import 시점에 예외를 던지면 키가 없는 빌드에서 무관한 화면까지 깨집니다.
- 비밀이 없을 때 **빈 값과 비교해 통과시키지 않습니다.** 401이 아니라 503으로 닫습니다.
- 부가 기능(알림 등)이 실패해도 **원래 쓰기를 실패시키지 않습니다.**

기록 규칙:

- **근거는 숫자로** — "점검 8/8", "테스트 185개", "넘침 0px"
- **못 한 검증은 ⚠️로** — 무엇을 못 했고 왜인지, 대신 무엇으로 확인했는지
- **리뷰 결과** — 🔴 · 🟠 개수와 반영 여부
- **새로 알게 된 사실과 함정** — 다음 세션이 같은 곳에서 시간을 쓰지 않게
- 비밀 값이 대화나 화면에 노출됐으면 9절에 **재발급** 항목을 추가

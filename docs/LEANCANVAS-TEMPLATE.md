# [프로젝트명] — 린 캔버스 (Lean Canvas)

> **린 캔버스란?** 사업 계획을 A4 한 장, 9개 칸으로 압축한 틀입니다. "누구의 어떤 문제를, 무엇으로, 어떻게 지속하며 해결하는가"를 한눈에 보게 합니다.
> PRD가 "무엇을 만들까"에 답한다면 린 캔버스는 그 앞의 **"왜 만들까"** 에 답합니다. 아이디어가 흐릿한 채 PRD를 쓰면 기능 목록만 길어집니다.

**📅 작성일**: YYYY-MM-DD
**🔗 근거 문서**: `docs/PRD.md`(기능 `F001`–`F0xx`), `docs/ROADMAP.md`, `CLAUDE.md`

**쓰는 법**

1. 이 파일을 `docs/LEANCANVAS.md`로 복사하고 `[대괄호]` 자리를 채웁니다. 안내용 인용문(`>`)은 다 쓴 뒤 지워도 됩니다.
2. 칸 번호가 곧 **작성 순서**입니다(① → ⑨). 문제와 고객을 먼저 정하고 해결안은 그 뒤에 씁니다.
3. 개인 프로젝트·사내 도구라면 **① 문제 · ② 고객군 · ⑧ 핵심 지표** 세 칸만 채워도 충분합니다. ⑥ 수익원은 "없음"이라고 적고 이유를 한 줄 답니다.
4. PRD를 아직 쓰지 않았다면 기능 ID 자리는 비워 두고, PRD를 쓴 뒤 돌아와 채웁니다.

> 여기서 가장 중요한 지표 하나가 PRD의 **"검증할 단 하나의 질문"** 으로 이어집니다.

| --- | --- | --- | --- |

## 이 캔버스가 다른 문서와 연결되는 방식

| 칸 | 이어지는 문서·위치 |
| --- | --- |
| ① 문제 · ② 고객군 | `docs/PRD.md` "핵심 정보", "사용자 여정" |
| ④ 해결안 | `docs/PRD.md` 기능 명세 → `docs/ROADMAP.md` Task |
| ⑤ 채널 | 진입 경로를 구현하는 Task, `CLAUDE.md`의 인증·라우팅 규칙 |
| ⑦ 비용 구조 | `CLAUDE.md` 스택, 운영 가이드 |
| ⑧ 핵심 지표 | `docs/PRD.md` "검증할 단 하나의 질문", 데이터 모델 |
| ⑨ 경쟁우위 | 계획서·설계 문서 |

PRD나 ROADMAP이 바뀌면 이 캔버스의 해당 칸도 함께 고칩니다. 특히 ④ 해결안의 기능 ID와 ⑧ 핵심 지표의 데이터 이름은 PRD와 일치해야 합니다.

## 작성 뒤 점검

- [ ] ① 문제가 "해결책이 없다"가 아니라 지금 겪는 불편으로 적혀 있다
- [ ] ② 고객군이 한 문장으로 좁혀져 있고 초기 사용자가 정해져 있다
- [ ] ④ 해결안의 모든 기능이 ① 문제 중 하나에 대응한다
- [ ] ⑧ 핵심 지표가 숫자이고, 어디서 확인하는지 적혀 있다
- [ ] 가장 중요한 지표 하나를 PRD의 "검증할 단 하나의 질문"으로 옮겼다
- [ ] 검증되지 않은 가설에는 가설이라고 적었다
